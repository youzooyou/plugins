**Goal:** Build `/ccs`, a new skill inside the `codex-stream-review` plugin that gives the same Claude+Codex adversarial-consensus outcome as `/cc`, built on a resumable Codex thread instead of a fresh process per round — with an automatic, read-only tmux progress pane when available.

**Spec:** `docs/2026-09-03-ccs-design.md` (read this first — this plan implements that design's decisions verbatim; if anything here seems to contradict it, the spec wins and this plan has a bug).

### Task 4: `codex-stream-review/scripts/watch-rollout.sh` — tmux narration companion

**Files:**
- Create: `codex-stream-review/scripts/watch-rollout.sh`

**Interfaces:**
- Produces: `watch-rollout.sh <rollout-file>` — tails the given rollout file and prints one human-readable narration line per meaningful event, until the process is killed (it never exits on its own — the caller's tmux pane or `Monitor` call owns its lifecycle).

- [ ] **Step 1: Write the script**

```bash
#!/usr/bin/env bash
set -u
ROLLOUT="${1:?usage: watch-rollout.sh <rollout-file>}"

# Wait for the file to exist -- it may not be created yet the instant this
# script starts (the caller races this against the THREAD_ID stderr signal,
# which fires before the rollout file is guaranteed to be on disk).
while [ ! -f "$ROLLOUT" ]; do sleep 0.5; done

tail -n +1 -F "$ROLLOUT" 2>/dev/null | while IFS= read -r line; do
  TYPE="$(printf '%s' "$line" | jq -r '.type // empty' 2>/dev/null)"
  case "$TYPE" in
    response_item)
      PTYPE="$(printf '%s' "$line" | jq -r '.payload.type // empty' 2>/dev/null)"
      case "$PTYPE" in
        reasoning)
          TEXT="$(printf '%s' "$line" | jq -r '.payload.content // [] | map(.text // empty) | join(" ")' 2>/dev/null)"
          [ -n "$TEXT" ] && printf 'reasoning: %s\n' "$TEXT"
          ;;
        custom_tool_call)
          CMD="$(printf '%s' "$line" | jq -r '.payload.arguments // empty' 2>/dev/null)"
          [ -n "$CMD" ] && printf 'investigating: %s\n' "$CMD"
          ;;
      esac
      ;;
    event_msg)
      PTYPE="$(printf '%s' "$line" | jq -r '.payload.type // empty' 2>/dev/null)"
      [ "$PTYPE" = "task_complete" ] && printf 'round complete\n'
      ;;
  esac
done
```

> **Finalized by Task 4 (2026-09-03):** the illustrative snippet above reads `.payload.arguments`
> for a `custom_tool_call` event; a live test against a real rollout file found the actual field is
> `.payload.input` instead. The shipped `codex-stream-review/scripts/watch-rollout.sh` uses
> `.payload.input` — treat that file's current code as authoritative, not the snippet above.
